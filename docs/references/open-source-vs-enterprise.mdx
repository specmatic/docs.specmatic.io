# Specmatic Open-Source vs Enterprise License Comparison

## High-level overview

| Capabilities | Open-Source (Free) | Enterprise | Details |
|---|---|---|---|
| Specification/Protocols supported | `OpenAPI/REST`,<br/>`WSDL/SOAP`,<br/>`MCP` | Everything in OSS plus<br/>`AsyncAPI`,<br/>`GraphQL`,<br/>`gRPC`,<br/>`Arazzo` workflows,<br/>`Avro` support,<br/>`Redis` stubbing,<br/>`JDBC` stubbing | [Protocol details](#protocol-details), [SOAP](/supported_protocols/soap), [MCP Auto Test](/getting_started/mcp_auto_test) |
| Contract testing | Yes for `OpenAPI/REST`, `WSDL/SOAP`, `MCP` | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows | [Protocol details](#protocol-details), [Backward Compatibility](/contract_driven_development/backward_compatibility) |
| API testing | No | Yes for `OpenAPI`, `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows with advanced value matchers | [Protocol details](#protocol-details), [Matchers](/features/matchers) |
| API workflow testing | Only for `OpenAPI` via config for workflows in the same spec | Yes, plus workflow orchestration across `OpenAPI` and `AsyncAPI` via `Arazzo` | [Workflows](/features/workflow), [Arazzo](/supported_protocols/arazzo) |
| API schema resiliency testing | `OpenAPI` only | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows | [OpenAPI details](#openapi-details) |
| API runtime resiliency testing | No | Yes for `OpenAPI`, including `202` monitor follow-through and `429` retry handling, plus `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows | [Smart Resiliency Orchestration](/contract_driven_development/contract_testing#smart-resiliency-orchestration), [OpenAPI details](#openapi-details) |
| Per test setup and teardown | No | Yes via `before` and `after` fixtures | [OpenAPI details](#openapi-details) |
| Intelligent Service virtualization | Yes for `OpenAPI/REST` (JSON and XML) and `WSDL/SOAP` APIs via stateless mocks | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC`, `Redis`, `JDBC`, and `Arazzo` workflows | [Service Virtualization](/contract_driven_development/service_virtualization), [Protocol details](#protocol-details) |
| Fault simulation | Yes, delays, errors, empty state etc... for `OpenAPI` and WSDL | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC`, `Redis`, `JDBC`, and `Arazzo` workflows | [Service Virtualization](/contract_driven_development/service_virtualization), [Protocol details](#protocol-details) |
| Backward compatibility testing | `OpenAPI` only | Yes, plus `AsyncAPI`, `GraphQL` and `gRPC` | [Backward Compatibility](/contract_driven_development/backward_compatibility), [Backward Compatibility Rules](/contract_driven_development/backward_compatibility_rules), [Protocol details](#protocol-details) |
| Specification and Example Generation | Yes for `OpenAPI` via proxy (live traffic), Postman collection, request/response payloads | Yes, plus `AsyncAPI` (Kafka) via `Studio` orchestration | [Service Virtualization](/contract_driven_development/service_virtualization) |
| Specification Enrichment | No | Yes for `OpenAPI`, `AsyncAPI` and `Arazzo` workflows via `Studio` |  |
| Specification Augmentation | Yes for `OpenAPI` across contract testing and mocking via `OpenAPI Overlay` Specification | Yes, plus `AsyncAPI` and `Arazzo` workflows | [Overlays](/features/overlays) |
| Adapters / hooks | No | Yes for test, mock and proxy via spec and request/response adapters | [Adapters](/features/adapters), [Configuration adapters](/references/configuration/adapters) |
| Dynamic domain-aware value generation | Yes for `OpenAPI` via dictionary, lookup or data substitution | Yes, plus dictionary generation via CLI and `Studio` | [Dictionary](/features/dictionary), [OpenAPI details](#openapi-details) |
| Example validation | `OpenAPI` only | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows including duplicate example detection | [OpenAPI details](#openapi-details) |
| Partial examples (Specify only what matters) | `OpenAPI` only | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows | [OpenAPI details](#openapi-details) |
| Meta-data Filter | `OpenAPI` only | Yes, plus `SOAP`, `AsyncAPI`, `GraphQL`, `gRPC`, `Redis`, `JDBC`, and `Arazzo` workflows | [Continuous Integration](/references/continuous_integration) |
| Coverage and Usage reports | HTML reports only for `OpenAPI` | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows, with HTML and `CTRF` reports | [Reports](/references/configuration/reports) |
| Governance report artifacts | JUnit XML | Plus, standalone `CTRF` report for testing and mocking; `SARIF` report for lint and backward compatibility | [Reports](/references/configuration/reports) |
| `OpenAPI` advanced feature support | Strong core engine for `test`, `mock`, `proxy`, `compatibility` and `example validation` | Everything in OSS plus richer mock handlers, linting, example management, dictionary generation, faker-backed data generation, and `Studio`-assisted authoring | [OpenAPI details](#openapi-details) |
| `AsyncAPI` / event-driven APIs | No | `AsyncAPI` and broker integrations with support for `JSON Schema`, `Avro` and `XSD` | [AsyncAPI](/supported_protocols/asyncapi), [Protocol details](#protocol-details) |
| `GraphQL` | No | Yes | [GraphQL](/supported_protocols/graphql) |
| Protobuf / `gRPC` | No | Yes | [gRPC](/supported_protocols/grpc) |
| `Arazzo` workflow testing and mocking | No | Yes | [Arazzo](/supported_protocols/arazzo) |
| `Redis` stubbing | No | Yes | [Redis](/supported_protocols/redis) |
| `JDBC` stubbing | No | Yes | [JDBC](/supported_protocols/jdbc) |
| `MCP Server` | `OpenAPI` only | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows | [MCP Auto Test](/getting_started/mcp_auto_test), [Protocol details](#protocol-details) |
| `Studio` (Visual Interface) | No | Yes | [Getting Started with Studio](/getting_started/studio_quick_start) |
| `Insights` (Continuous Governance) | No | Yes | [Insights](/enterprise_onboarding/insights/overview) |
| API Security | Yes for `OpenAPI` across contract testing, mocking and proxy with HTTP/mTLS and security schemes | Yes, plus `AsyncAPI`, `GraphQL`, `gRPC` and `Arazzo` workflows | [Authentication](/features/authentication) |
| Support model | Standard open-source support via GitHub Issues | Dedicated support portal with 24-hour TAT | [Migrating to Specmatic Enterprise](/references/migrating_to_enterprise) |

## OpenAPI details

| OpenAPI capability | Open-Source (Free) | Enterprise | Details |
|---|---|---|---|
| Contract testing | Contract tests against `OpenAPI` specs, including filters, external example directories, strict mode, lenient parsing, and JUnit output | Everything in OSS plus enterprise protocol coverage | [Continuous Integration](/references/continuous_integration) |
| API testing | No | Yes with [advanced value matchers](/features/matchers) |
| API workflow testing | Yes for `OpenAPI` via config for workflows in the same spec | Yes, plus workflow orchestration across `OpenAPI` and `AsyncAPI` via [`Arazzo`](/supported_protocols/arazzo) |
| API runtime resiliency testing | No | Yes, with `429` retry and `202` monitor follow-through, subject to the documented requirements and retry limits | [Smart Resiliency Orchestration](/contract_driven_development/contract_testing#smart-resiliency-orchestration) |
| Per test setup and teardown | No | Yes via `before` and `after` fixtures |
| Intelligent Mocking | Mock server with strict mode, pass-through target, hot reload, delays, filtering, config-backed loading, and external examples | Everything in OSS plus richer mock handlers and additional internal verification/retrieval flows | [Service Virtualization](/contract_driven_development/service_virtualization), [Mock Configuration](/references/configuration/mock-configuration) |
| Proxy recording | Captures traffic and converts it into contracts and mocks | Everything in OSS plus Live proxy with `Studio`-assisted workflows around proxy and spec evolution | [Service Virtualization](/contract_driven_development/service_virtualization), [Docker Images](/references/docker_images) |
| Backward compatibility | `OpenAPI` backward compatibility checks | Everything in OSS plus Insights integrations to provide richer validations | [Backward Compatibility](/contract_driven_development/backward_compatibility), [Backward Compatibility Rules](/contract_driven_development/backward_compatibility_rules) |
| Validation | `OpenAPI` spec and example validation | Everything in OSS plus duplicate/competing example detection controls |
| Example validation scope | Inline examples, external examples, single files, single dirs, and multi-spec trees | Everything in OSS |
| Example export | No | `examples export` to externalize inline examples | [Service Virtualization](/contract_driven_development/service_virtualization) |
| Dictionary generation | No | `examples dictionary` and `Studio`-driven dictionary generation workflows | [Dictionary](/features/dictionary) |
| Example generation | No | Example generation with filtering, dictionary input, and `only mandatory keys` mode | [Dictionary](/features/dictionary) |
| Example auto-fix | No | One-click `auto-fix` invalid examples |
| Example import | No | Import external examples back into `OpenAPI` files | [Service Virtualization](/contract_driven_development/service_virtualization) |
| Adapters / hooks | No | Yes for test, mock and proxy via [spec and request/response adapters](/features/adapters) | [Adapters](/features/adapters), [Configuration adapters](/references/configuration/adapters) |
| Interactive example workflow | No | Interactive example server in `Studio` for advanced example management workflow including partial examples |
| Faker-backed data generation | No | Faker-backed string generation using `datafaker`, including alias-based and context-aware generation |
| Linting | No | Enterprise-grade linting solution with semantic intelligence, rule-packs and DSL for custom rules |
| Visual authoring | No | `Studio` provides an intuitive visual UI for spec and example validation, dictionary generation, and enrichment flows |
| Spec enrichment from observed traffic | No | Merge observed undeclared responses back into the `OpenAPI` spec via `Studio` |
| Reporting | HTML coverage reporting for `OpenAPI` | Everything in OSS plus standalone governance-oriented `CTRF` and `SARIF` report artifacts | [Reports](/references/configuration/reports) |
